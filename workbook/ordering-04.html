RAW — Different Masters

Case 4 of 10 · Two masters, one address — where AXI4 stops being enough
—

0 Background read this first — context before mechanics

Case 3 showed that a write and a read from one master are unordered. When the write and the read come from different masters, the situation is worse: there is no mechanism within AXI4 to fix it at all.

Why the single-master fix does not transfer

In case 3 the master could wait for its own BRESP before issuing the read. Here the reader is a different master. It has no visibility of the writer's write response, no way to know a write is in flight, and no shared ordering domain — after ID expansion (case 9) the two masters necessarily carry different IDs at the slave anyway.

M0: AW/W → B // M0 knows when its write completed
M1: AR → R // M1 knows nothing about M0's write

// no shared event, no shared ID, no ordering

What the reader can observe

Three outcomes, all legal:

OutcomeWhen it happens
Old valueThe read is served before the write commits
New valueThe write commits first
Torn valueMulti-beat write partially committed when the read is served — some beats new, some old

The third is the one people forget. A single-beat write to an aligned location within the bus width is atomic in practice, but a burst is not. A reader can observe a cache line half-updated.

What AXI4 does not solve

This is the boundary of the protocol. AXI4 orders transactions from one master; it says nothing about visibility between masters. Multi-master coherency requires either a coherency protocol (ACE, CHI), explicit software synchronisation, or architectural constraints that keep masters off shared addresses.

The three real solutions

Software synchronisation. The writer completes its write, waits for BRESP, then sets a flag; the reader polls the flag before reading the payload. This works only if the flag and payload orderings are themselves guaranteed — which is why the flag write usually carries device attributes, so its response means it has actually landed.

Hardware coherency. ACE adds snoop channels so a write invalidates or updates other masters' cached copies. CHI generalises this for many-core systems. This is the right answer when masters genuinely share data at high frequency.

Architecture. Route both masters through the same interconnect port so they share an ordering domain, or partition memory so no address is written by one master and read by another without an explicit handoff.

Recognising it in the field

Symptoms are intermittent and correlate with core count, load, and memory type rather than with the code path. Adding a print statement or a delay in the reader often makes it disappear. If two different masters touch the same address and one of them writes, treat this as the first hypothesis rather than the last.
