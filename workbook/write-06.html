FIXED Burst Write

Case 6 of 10 · Every beat writes the same address — filling a hardware FIFO
—

0 Background read this first — context before mechanics

FIXED on the write side is the mirror of FIXED on the read side. The address is a port, not a location, and every beat pushes another entry into whatever sits behind it.

The model

A transmit FIFO occupies one address. Writing to it enqueues a byte and advances an internal pointer. Four writes to that address enqueue four bytes; four writes to four consecutive addresses hit four unrelated registers.

// UART transmit FIFO at 0x5000, sending "Help"

FIXED, 4 beats → 0x5000 ×4
enqueues 'H' 'e' 'l' 'p' ✓

INCR, 4 beats → 0x5000, 0x5001, 0x5002, 0x5003
writes 'H' to the FIFO, then corrupts three registers ✗

Why the write case is worse than the read case

An INCR read of a peripheral returns wrong data and may trigger read side effects. An INCR write actively changes three registers you never intended to touch. Where a stray read might clear a status bit, a stray write can reconfigure a peripheral mid-operation, disable an interrupt, or set a control field to whatever byte of the payload happened to land there.

Failure signature

The data you meant to send is partly transmitted; meanwhile the peripheral reconfigures itself for no visible reason. Baud rate changes, interrupts stop firing, a channel disables. The symptom looks like a peripheral fault and the cause is a burst type.

Where FIXED writes appear

TargetWhat each beat does
UART / SPI TX FIFOEnqueues one byte for transmission. A short FIXED burst fills the FIFO with one address phase
Hardware mailboxEach write posts a message word into a queue read by another core
Command queue portGPU and DMA engines often accept command words through a single doorbell-style register
Streaming accelerator inputA fixed input port fed word by word, with the accelerator consuming as it goes

Constraints

AWLEN+1 is capped at 16 for FIXED, same as the read side, and for the same reason: you are feeding a small hardware structure that can stall, and a long burst to a full FIFO would hold the write data channel indefinitely.

WSTRB still applies per beat. On a byte-wide FIFO port with AWSIZE=3'b000, only one strobe bit is meaningful, and it should be set — a beat with WSTRB=0 writes nothing and therefore enqueues nothing, silently shortening your message by one byte.

What the slave must be

FIXED is only meaningful against a slave whose write has a side effect beyond storing a value. Issue it to ordinary memory and all four beats overwrite the same location — the last one wins and the first three are lost. That is legal and pointless. The dangerous direction, again, is the reverse: INCR aimed at a port-style slave.
