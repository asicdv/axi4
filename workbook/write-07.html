WRAP Burst Write

Case 7 of 10 · Cache line writeback starting at the dirty word
—

0 Background read this first — context before mechanics

WRAP writes exist for cache line eviction. The mechanics are identical to the read side; the motivation is different, and worth understanding because it explains why WRAP writes are rarer than WRAP reads.

Why a writeback would wrap

A cache evicts a dirty line. It must write the whole line back, and it can start anywhere within it. Starting at the base with INCR is perfectly correct — so why does WRAP exist on the write side at all?

The answer is symmetry of the datapath. A cache that has just performed a WRAP read to fill a line has its buffer indexed from the critical word. Evicting that line with a matching WRAP write means the data leaves the buffer in the same rotation it arrived in, with no re-ordering logic between the buffer and the bus. It is a hardware simplification, not a latency win.

// 16-byte line, dirty word at offset 0xC

INCR from 0x1000 → 0x1000, 0x1004, 0x1008, 0x100C
requires a rotate before transmit
The key difference from reads

A WRAP read has a genuine performance motive — the CPU resumes three beats earlier. A WRAP write has no such benefit: nobody is waiting on a particular word of a writeback. Its value is purely in avoiding a rotation in the cache's datapath.

The rules, unchanged

Everything from the read side applies exactly. AWLEN+1 must be 2, 4, 8 or 16. AWADDR must be aligned to the transfer size. The burst is confined to an aligned block of (AWLEN+1) × 2^AWSIZE bytes:

wrap_size = (AWLEN+1) × 2^AWSIZE
base = AWADDR & ~(wrap_size − 1)
addr(n) = base + ((AWADDR − base + n × 2^AWSIZE) mod wrap_size)

And the same consequence follows: a WRAP burst cannot cross a 4KB boundary, because it never leaves its own aligned block and the block is at most 2KB.

Where you should not see it

WRAP writes belong to caches and cache-like agents. A DMA engine copying a buffer, a display controller, a network MAC — none of these have a critical word or a rotated buffer, so a WRAP write from any of them is a configuration error.

The symptom when it happens is specific and worth recognising: the destination region contains the correct bytes rotated within each block. If the start address happens to be block-aligned the rotation is zero and everything looks fine, so the bug appears only for particular buffer addresses — which makes it look data-dependent rather than like a burst-type mistake.
