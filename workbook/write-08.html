Write Strobes

Case 8 of 10 · WSTRB — byte-level masking with no read-side equivalent
—

0 Background read this first — context before mechanics

WSTRB is the signal that has no counterpart on the read channel. It carries one bit per byte lane and decides, per beat, which bytes are actually written. Everything about partial writes, read-modify-write avoidance, and unaligned access handling flows from it.

Why writes need it and reads do not

A read that returns more bytes than the master wanted is harmless — the master ignores the extra lanes. A write that stores more bytes than intended corrupts memory the program never touched. The asymmetry is not stylistic: writes are destructive, so they need byte-level control that reads do not.

// 32-bit bus, WDATA = 0xDEADBEEF, memory initially 0x11223344

WSTRB = 4'b1111 → memory becomes 0xDEADBEEF
WSTRB = 4'b0110 → memory becomes 0x11ADBE44 // lanes 1,2 only
WSTRB = 4'b0001 → memory becomes 0x112233EF // lane 0 only
WSTRB = 4'b0000 → memory unchanged // legal!

Note the last line. A beat with WSTRB=0 is entirely legal and writes nothing. It still consumes a beat, still needs a handshake, and still counts toward AWLEN+1. It is not an error and produces no error response.

What it is for

UseHow WSTRB carries it
Sub-word storeA byte or halfword store on a wide bus. Only the lanes covered by the architectural access are strobed; the rest of the word is preserved
Unaligned accessAn access straddling a bus word becomes two beats, each strobing only its own portion
Merged writesA write buffer combining several sub-word stores into one wide beat sets the union of their strobes
Burst paddingA WRAP burst padded to a legal power-of-two length uses zero-strobe beats for the padding
Why this matters for memory design

Without WSTRB, a byte store to DRAM would require a read-modify-write: fetch the word, merge the byte, write it back. Byte enables push that merge into the memory itself, turning a three-step operation into one. This is why every real memory interface has byte enables and why WSTRB maps onto them directly.

Where it goes wrong

The most common bug is a slave that ignores WSTRB entirely and writes all lanes unconditionally. Every full-word write works perfectly, so the slave passes basic tests. The failure appears the first time software does a byte store: the three neighbouring bytes are silently overwritten with whatever the master left on the unused lanes.

The second common bug is on the master side — computing strobes from the wrong address bits on a narrow or unaligned access, so the right data goes to the wrong lanes. Since the beat count and burst structure are all correct, nothing on the bus looks unusual.

Both bugs are silent. There is no error response for a strobe mistake, because from the protocol's point of view nothing invalid happened.
