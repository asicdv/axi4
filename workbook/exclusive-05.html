Exclusive Burst

Case 5 of 8 · Multi-beat atomicity — updating a whole structure indivisibly
—

0 Background read this first — context before mechanics

Exclusive access is not limited to single words. A burst can be exclusive, which lets a master read a multi-word structure, modify part of it, and write the whole thing back atomically.

What this buys you

A single-word exclusive sequence protects one machine word. Many real data structures are larger: a queue entry with a pointer and a length, a lock plus its owner ID, a descriptor with several fields. Updating those with several separate atomic operations leaves windows in which another observer sees a half-updated structure.

// four separate single-word atomics
atomic_write(f0); ← observer can read here
atomic_write(f1); ← and here
atomic_write(f2); ← and here

// one exclusive 4-beat burst
excl_read(16B) … excl_write(16B) → all four fields, or none

How it works

The monitor reserves the whole region covered by the burst, not just the first address. Any write anywhere in that region invalidates the reservation. RRESP=EXOKAY appears on every beat of the read, not only the last.

Everything must match

The exclusive write must repeat the read's address, ID, AWLEN, AWSIZE and AWBURST exactly. A shorter or longer burst is not the transaction the reservation covered, and the behaviour is undefined.

A consequence people miss: you must write back every beat, including the ones you did not modify. The transaction is defined by its length, so a four-beat reservation requires a four-beat write. Unchanged fields are written with the values you just read.

Limits

LimitReason
Monitor granularityThe reservation covers an aligned region of at least the burst size — often a full cache line, so unrelated neighbours can break it (case 7)
Maximum sizeImplementation-defined. Many monitors support only up to one cache line; larger exclusive bursts may simply never succeed
AlignmentThe region must be aligned. An unaligned exclusive burst spanning two granules is unlikely to be supported
Contention windowA longer burst takes longer, so the window in which a reservation can be broken is wider — failure rates rise with size

When to reach for it

Use an exclusive burst when several fields genuinely must change together and an observer must never see a mixture. A queue entry whose pointer and length must be consistent is the canonical case.

Do not use it merely to save transactions. The wider reservation is easier to break, so a large exclusive burst under contention can fail far more often than several small ones would — and unlike small ones, every failure discards the whole attempt.
