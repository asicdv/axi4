WAW — Same ID

Case 1 of 10 · Two writes, one address, shared ID — last write wins
—

0 Background read this first — context before mechanics

This is the one ordering case that behaves exactly as intuition expects, which makes it the right place to start. Establish precisely why it works here, and every later case becomes a question of which of those conditions has been removed.

Three guarantees stack up

Two writes to the same address with the same AWID. Three separate rules combine, and it is worth separating them because later cases break them one at a time.

ChannelWhat guarantees the order
AWThe master issues A before B, and the slave accepts in that order
WAXI4 requires write data in AW-acceptance order regardless of ID — this rule is unconditional
BSame-ID responses must return in address order — this is what the shared ID adds
MemoryBecause data arrives in order and the ID forces the effects to be ordered, A is committed before B

The result is deterministic: memory ends at 0xBBBB, every time, on every implementation. Software can rely on "the last write wins" and does, constantly.

Mem@0x1000: OLD → 0xAAAA → 0xBBBB
// deterministic, because the same ID orders the effects

What software builds on this

Almost every initialisation sequence assumes it. Write a default, then write the real value. Clear a field, then set it. Store a structure member twice as a computation refines. None of these are exotic — they are ordinary code, and they all depend on same-address writes landing in program order.

Where the guarantee ends

This ordering is between writes, from one master, sharing an ID. Remove any one of those three conditions and the guarantee disappears. Case 2 removes the shared ID; case 3 makes the second access a read; case 4 introduces a second master.

Ordering versus visibility

One distinction to hold onto. The guarantee is that A takes effect before B — their relative order. It is not a guarantee about when either becomes visible to another observer. With bufferable memory both writes may sit in an interconnect write buffer after their responses return.

What you can rely on is that no observer will ever see B without also seeing A, because the order is preserved wherever they are held. That is a weaker claim than "the data is in memory" and it is the correct one.
