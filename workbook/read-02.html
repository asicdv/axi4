Burst Read — INCR

Case 2 of 8 · Multi-beat incrementing burst with mid-burst backpressure
—

0 Background read this first — context before mechanics

The incrementing burst carries almost all of the useful traffic in a modern SoC. Everything else in AXI4 — the ID system, the ordering rules, the response codes — exists to let many of these run at once without stepping on each other.

The problem bursts solve

Every transaction pays a fixed cost on the address channel: one AR handshake, plus whatever arbitration and decode latency the interconnect adds before the slave even sees it. If you fetch 32 bytes as eight separate 4-byte reads, you pay that cost eight times. Fetch it as one burst and you pay it once.

// 32 bytes from DDR, 64-bit bus, ~5-cycle interconnect overhead per address
8 × single-beat → 8 AR handshakes + 8 × 5 cyc overhead = ~48 cycles
1 × 4-beat burst → 1 AR handshake + 1 × 5 cyc overhead = ~9 cycles

// and the AR channel is now free for other masters 7/8 of the time

The second effect matters as much as the first. Address-channel bandwidth is a shared resource. A master that bursts leaves room for other masters to issue their own requests, which is why burst discipline is a system-level concern and not just a local optimisation.

Where you meet this exact transaction

The configuration in this case — four beats of eight bytes, incrementing — is a 32-byte aligned fetch, the natural size for several very common operations:

WhereWhat it is doing
CPU cache line fillA load misses in L1. The cache controller fetches the whole line so neighbouring accesses hit. Line size sets the burst length; a 64-byte line on a 64-bit bus is ARLEN=7, ARSIZE=3'b011
DMA descriptor fetchA DMA engine reads its next descriptor — source, destination, length, flags — from a ring in memory. Descriptors are typically 16 or 32 bytesARLEN=1…3, ARSIZE=3'b011
Display scanoutThe display controller streams the framebuffer line by line, at fixed rate, forever. Long bursts keep its FIFO fed and reduce DDR row thrashARLEN=15, ARBURST=INCR
GPU texture fetchTexels are read in tiles. Tile size and burst length are chosen together so one burst maps to one DDR row activation
Ethernet RXPacket payload moves from MAC buffer to system memory in bursts sized to the interconnect's efficiency sweet spot, not to the packet
Design tension

Longer bursts are more efficient but hold the data channel longer, which raises worst-case latency for everyone else. A display controller wants 16-beat bursts; a CPU waiting on a load wants to be served immediately. This is the tension that ARQOS, interconnect arbitration, and burst-length caps in DMA engines all exist to manage.

Why the stall in this case is realistic

The master de-asserts RREADY for one cycle mid-burst. In real silicon this is not an anomaly — it is the normal behaviour of a master whose receive path is not infinitely fast. Common causes:

Receive FIFO nearly full. The master's buffer is draining into a slower downstream consumer. It de-asserts RREADY to avoid overflow. This is the single most common reason.

Clock domain crossing. The master runs slower than the slave, or an async FIFO in between needs a cycle to update its pointers. The gap propagates back as intermittent RREADY de-assertion.

Write-back contention. The master is simultaneously writing a previous cache line and cannot accept new fill data until a port frees up.

The protocol requirement that follows — that the slave hold RDATA, RID, RRESP, and RLAST perfectly stable through the stall — is what makes the master's life simple. It can pause for one cycle or two hundred and the data will still be there, unchanged, when it returns.

What this case is really teaching

Three things, in increasing order of how often they bite people:

1. Encoded fields. ARLEN and ARSIZE are both encoded, not literal. Beat count is ARLEN+1; bytes per beat is 2^ARSIZE. Nearly every off-by-one bug in AXI RTL traces back to forgetting one of these.

2. Stability across a stall. The rule looks obvious written down and is routinely violated in RTL where RDATA is driven combinationally from a memory array that keeps advancing. It produces silent corruption with no error response.

3. RLAST position. It must land on beat ARLEN, zero-indexed. Assert it early and the master retires the transaction while beats are still in flight; assert it late or never and the transaction never retires at all.
